## Measurement limitations

- Execution over WinRM makes the parent process wsmprovhost.exe rather than an interactive shell. Rules keyed on ParentImage will behave differently here than under manual execution. The rules in this lab key on commandLine, so they are unaffected — but a future ParentImage rule must be validated manually as well.
- Defender real-time protection must be ON for an honest run. A prevented technique is a valid outcome and is recorded as such, not retried with protection disabled.

## How grades are assigned

A detection counts as coverage only when a rule fires *specifically* on
the technique executed. A rule that alerts on every PowerShell process is
not coverage for T1059.001 - it is noise that trains analysts to ignore
PowerShell. The scorer therefore requires an ATT&CK technique match, not
merely an alert inside the window: the runner drives Atomic through
PowerShell, so the harness itself trips the PowerShell rules on almost
every step, and counting that would report coverage the lab does not have.

Latency is measured from the end of attack execution to the first matching
alert, not from the start of the tool invocation - a two-minute subnet scan
would otherwise appear to have a two-minute detection delay.
